# 全局测试经验（跨项目，持续进化）

> 阶段 0 读这里开局生效；阶段 4 有新通用教训就追加。一行一条：`[标签] 教训 — 应用：怎么用`。超 40 行修剪旧条目。

## 环境类

- [环境] Windows/Git Bash 下路径含空格必须引号，统一用 /d/xxx 形式 — 应用：所有 shell 命令先检查路径引号
- [环境] python 与 python3 因机器而异 — 应用：先 `command -v python python3` 探测再调用
- [环境] Node ≥18 自带 `node --test`，零依赖可写单测 — 应用：项目无测试框架时的第一降级手段
- [环境] Git Bash 控制台把 UTF-8 中文显示成乱码（GBK 控制台所致），非服务端 bug — 应用：curl 输出中文乱码时先 `| xxd | head` 验字节再下结论（来源：todo-api 冒烟 2026-10-30）

## 流程类

- [流程] 先跑项目自带测试套件再自己动手 — 应用：解剖阶段探测出的测试命令最先执行，红了先分清是"本来就坏"还是"环境问题"
- [流程] README 宣称与代码实际的差异是高产地 — 应用：解剖时必做两列对照，差异即测试点
- [流程] 每个失败结论必须当场留证据（命令+输出） — 应用：测试中即时记录，事后回忆必失真

## 手法类

- [手法] Express/Flask 类服务默认几乎不校验输入 — 应用：空 body、错误类型、超长字段优先打
- [手法] 空输入直接回车是最便宜的 bug 探针 — 应用：每个表单/接口第一步就试空提交
- [手法] 负数与零是数值字段的高频漏网鱼 — 应用：所有金额/数量/分页参数必测 0 和 -1

## API / 契约类（v1.0 蒸馏）

- [手法] 对象 ID 来自客户端且服务端只凭 ID 取数 → BOLA 是头号嫌疑，A 的 token 打 B 的 ID 必测 — 应用：每个 `:id` 端点补一条越权用例（OWASP API1:2023）
- [手法] 错误响应应带 `Content-Type: application/problem+json`，且 `status` 成员与实际 HTTP 码一致 — 应用：所有 4xx/5xx 抽查这两个判据（RFC 9457）
- [手法] 把 500 当"参数错误"记下来是漏报，500 永远是 bug — 应用：异常参数矩阵里单独统计 5xx 数量
- [手法] 有 OpenAPI 就先跑 schemathesis 再手写用例，它自动生成负例且自带最小 curl 复现 — 应用：解剖阶段发现 openapi.json 时优先执行
- [手法] 只验响应码不验 DB 状态会漏掉副作用 bug — 应用：写操作双重断言（响应 + 库/缓存/事件）
- [手法] 分页合并后的集合应等于全量集合 — 应用：用蜕变关系测分页，无需预知总数

## 安全类（v1.0 蒸馏）

- [安全] 批量分配（请求体塞 role/price/user_id）与过度暴露（响应带 password/hash）同属 API3 属性级授权缺失 — 应用：每个写接口测多余字段，每个读接口查响应白名单
- [安全] 静态审查也能出结论：`.env` 是否入库、密钥硬编码、`CORS: *`、废弃 `/v1/` 与 `/debug` 在线 — 应用：项目跑不起来时用 `git grep` + 路由盘点兜底
- [安全] 疑似密钥/漏洞写"待确认"，不写"已泄漏" — 应用：静态扫描结论一律标注推定性质
- [流程] 认证授权矩阵按「匿名/本人/他人/管理员」四列填满再逐格实调，空白格即未测风险 — 应用：API 项目计划阶段先画矩阵

## 性能类（v1.0 蒸馏）

- [手法] 平均值会骗人，必须报 p50/p95/p99 + 样本数 — 应用：任何"挺快"的结论都要补分位数，否则标注"单点观测"
- [手法] 并发数 ≈ 吞吐(RPS) × 平均响应时间(s)（Little's Law） — 应用：反推该压多少 VU，不拍脑袋定"100 并发"
- [手法] 一个请求发出几十条 SQL 是 N+1 的最快信号 — 应用：开 query logging 数查询条数，比先做优化更便宜
- [流程] 本机 localhost 结果不代表生产，报告必须写局限 — 应用：性能段落固定附一行"无网络延迟/数据量差异"
- [安全] 压力/浸泡/尖峰只在隔离的授权环境做 — 应用：默认只跑冒烟 + 轻量负载，禁止打外部服务

## 前端 / 全栈类（v1.0 蒸馏）

- [手法] 前端最高产的检查是五态矩阵（loading/empty/error/success/partial），缺一态即 bug — 应用：用 route 拦截 mock 出 500/空/延迟，无需改后端
- [手法] 4xx 不自动重试、5xx 最多 3 次退避重试 —— 应用：逐状态码核对前端错误映射与重试逻辑
- [手法] 占位资源 URL 与引用不存在的本地媒体是静态可查的硬失败 — 应用：grep unsplash/picsum/placeholder 并逐个核对媒体文件存在
- [流程] 集成测试用真 DB（事务回滚/testcontainers），只有单测才 mock repository — 应用：别把"跑得飞快"当成"验到了"
- [流程] 回滚预案没演练过就等于没有；"CI 过了"不等于六门禁过了 — 应用：发布验收逐门留证据再打 12 分

## 有效性 / AI 类（v1.0 蒸馏）

- [手法] 高覆盖率 + 低变异得分 = 一堆假测试 — 应用：核心模块抽查断言强度，警惕只断言 `is not None` 的伪测试
- [工具] 给 CI 加 `retries: 3` 不是修 flaky，是把不确定性藏起来 — 应用：先定位共享状态/异步等待/外部依赖，修不好才 quarantine 并登记
- [AI] Playwright healer 让测试变绿不等于 bug 被修了，它可能放宽了断言 — 应用：任何 AI 改过的断言都做人工 diff 复核
- [AI] 「用 AI 写测试」(AI for QA) 与「测 AI 系统」(Testing for AI) 方法完全不同 — 应用：先判能力层，后者改用不变量/蜕变关系/评测集而非单点期望值
- [AI] 非确定性系统单次观测不构成结论 — 应用：同 prompt ≥5 次采样，报样本数与分布，别让同一模型既当被测又当唯一裁判
- [流程] 静态记录 ≠ 评测准备度 ≠ 运行时质量 ≠ 发布批准 — 应用：文件/目录数量增加只证明第一种，报告不许混用
