# 隐私与数据生命周期测试（阶段 3 · 横向叠加）

> 蒸馏自 OWASP API Security Top 10:2023（API3 过度数据暴露 / 批量分配）、OWASP Top 10 Privacy Risks、GDPR 第 5 条（数据最小化/存储限制）与第 17 条（删除权）、OWASP Logging Cheat Sheet。`CHANGELOG.md` v1.3.0 记录逐条来源 URL。
> 定位：前面所有安全手册测的是「**能不能越权拿到数据**」；本手册测的是「**系统该不该存这些数据、存了能不能删、返回时有没有多给、日志里有没有漏**」。这是合规与信任维度，和越权是两件事。

## 0. 适用边界与分工

| 触发 | 叠加本手册 | 不适用 |
|---|---|---|
| 处理个人数据 / PII / 用户生成内容 / 有隐私政策或合规要求（GDPR/个保法/CCPA） | 是 | 纯技术工具、不处理任何个人数据 → 只写「未做隐私合规验证」 |
| 有「导出/删除/注销」功能、日志含用户数据 | 是 | 日志与响应均不含任何 PII 的离线脚本 → 标注缺口 |
| 只关心越权读取他人数据 | 去 `references/security-testing.md` | 本手册不重复 BOLA/IDOR 用例 |

**三条认知打底**：
1. **「用户能访问自己的数据」≠「系统可以无限留存和滥用」**：GDPR 第 5 条要求**数据最小化**与**存储限制**——不该收集的别收集，该删的到点删。
2. **「接口返回成功」≠「没多给」**：API3:2023 的过度数据暴露指响应里夹带了密码哈希、token、身份证号等敏感字段；客户端只要一个 `name` 却回了整个用户对象。
3. **「日志记全了方便排查」≠「合规」**：OWASP Logging Cheat Sheet 明确：token、密码、PII 不得进日志；日志注入也要防。

## 1. 数据分类与最小化（GDPR Art.5）

| 原则（Art.5，转述） | 测试动作 | 通过判据 |
|---|---|---|
| 数据最小化（data minimisation） | 逐字段核对「表单/接口实际收集」与「业务必要项」 | 无必要字段（如注册只要邮箱却收身份证）即缺陷 |
| 目的限制（purpose limitation） | 查数据后续使用是否超出采集时声明的目的 | 用途超出声明且无新授权 → 缺陷 |
| 存储限制（storage limitation） | 查是否有留存期限/TTL/归档策略 | 无过期机制的长期留存 PII → 缺陷 |
| 完整性与保密性 | 查 PII 的加密/访问控制 | 明文 PII、无访问控制 → S1/S2 缺陷 |

## 2. 过度数据暴露与批量分配（OWASP API3:2023）

- **过度数据暴露（Excessive Data Exposure）**：响应体返回了客户端不需要的敏感属性。
  - 测试：每个读接口用**最小权限/普通用户**调用，逐字段比对响应与「该角色所需白名单」。
  - 判据：响应含 `password`/`passwordHash`/`token`/`secret`/`ssn`/`idCard`/`salary` 等敏感字段 → **S1 缺陷**（API3）。
- **批量分配（Mass Assignment）**：写接口把请求体里的敏感属性（如 `role`、`isAdmin`、`price`、`userId`、`balance`）直接绑定到对象。
  - 测试：写接口请求体**额外塞入**上述字段，看是否被服务端采信。
  - 判据：服务端接受并生效了未授权属性 → **S1 缺陷**（API3）。

## 3. 日志与追踪中的 PII 处理（OWASP Logging Cheat Sheet）

| 规则（转述） | 测试动作 | 通过判据 |
|---|---|---|
| 不记录 PII / 令牌 / 密码 | 触发带敏感数据的请求，查日志/span 属性 | 日志中无明文 token、密码、完整卡号、身份证 |
| 防范日志注入（log forging） | 输入含换行/分隔符/控制字符，查日志是否被伪造新行 | 输入被编码/转义，不产生伪造日志条目 |
| 数据最小化于日志 | 查日志是否记录超出排查必要的字段 | 无整段请求体/响应体入库 |
| 结构化 + 统一字段 | 查日志是否可机读、字段命名一致 | 便于脱敏审计，非必填但建议 |

> 与 `references/observability-testing.md` 的「span 属性脱敏」是同一目标的不同切面：那里查 trace，这里查日志落盘内容。

## 4. 删除权与数据生命周期（GDPR Art.17）

「被遗忘权」要求：在以下情形**无不当延迟**地删除个人数据——撤回同意、数据不再为原目的所需、非法处理等；并对**接收方、链接、副本、复制**负有通知与处置义务。

| 测试动作 | 通过判据 |
|---|---|
| 触发「删除/注销」后，查主库该用户记录是否移除或匿名化 | 记录不可再通过正常接口检索到 |
| 查关联数据（缓存、备份、日志、导出副本、搜索索引、CDN 缓存） | 副本/索引/缓存中同样不可复原（或标注为不可检索的脱敏态） |
| 查对外/对第三方的传播（webhook、下游同步、数据共享方） | 有对已传播数据的删除/通知机制，而非只删主库 |
| 查删除是否为**硬删除或不可逆匿名化** | 软删除但密钥仍可被内部轻易还原且无审计 → 标注风险 |

> 诚实标注：备份通常按保留周期清理，验证时写明「备份中的残留是否在保留期满后清除」，而非假设实时清除。

## 5. OWASP Top 10 Privacy Risks（映射为测试视角）

> 编号取自 OWASP《Top 10 Privacy Risks》列表；落地时按项目实际数据处理链路逐条核对，不要求全中。

| 风险（精简命名） | 测试关注点 |
|---|---|
| P1 数据传输同意 / P2 数据处理同意 | 采集前是否取得与声明一致的同意；用途变更是否重新授权 |
| P3 无理监视 | 是否超范围收集行为/位置/设备指纹 |
| P4 不安全的数据存储 / P5 不安全的数据传输 | PII 是否加密存储与传输（TLS、静态加密） |
| P6 不透明的政策 | 隐私政策是否与代码实际行为一致（文档 vs 代码差异） |
| P7 未经同意的二次利用 | 数据是否被用于采集时未声明的目的 |
| P8 主动联系骚扰 | 联系方式是否被过度收集/外发 |
| P9 数据泄露 | 越权/注入/日志泄漏是否导致 PII 外泄（联动 `security-testing.md`） |
| P10 不合规 | 是否满足所宣称的法规（GDPR/个保法/CCPA） |

## 6. 测试卡（P-1 ~ P-12）

| # | 测试动作 | 通过判据 | 常见失败 |
|---|---|---|---|
| P-1 | 字段级分类：列出所有 PII 字段 | 有分类表，敏感字段明确标注 | 无数据字典、PII 散落各处 |
| P-2 | 每个读接口响应逐字段比对白名单 | 无越权敏感字段返回 | 响应夹带 token/哈希/证件号 |
| P-3 | 写接口批量分配（塞 role/price/userId） | 额外字段被忽略或拒绝 | 越权改角色/改价成功 |
| P-4 | 注册/采集最小化核对 | 只收业务必要字段 | 过度采集身份证/位置 |
| P-5 | 存储期限/TTL 检查 | PII 有留存上限与清理 | 永久留存无策略 |
| P-6 | 删除/注销后主库核查 | 记录不可检索 | 软删除但可被复原且无审计 |
| P-7 | 删除后缓存/索引/副本核查 | 副本同样不可复原 | 只删主库，CDN/搜索仍有 |
| P-8 | 日志 PII 核查 | 无明文 token/密码/PII | 日志泄漏令牌 |
| P-9 | 日志注入核查 | 输入被转义，无伪造行 | 换行注入伪造日志 |
| P-10 | 传输加密核查 | PII 全程 TLS / 静态加密 | 明文传输或存储 |
| P-11 | 同意与政策一致性 | 代码行为 = 隐私政策声明 | 政策说不收集实际在收集 |
| P-12 | 对外传播删除机制 | 有对下游/第三方的删除通知 | 只删本地，外发数据仍在 |

## 7. R-6 隐私与数据生命周期（可证伪规则，见 SKILL.md）

| 声称 | 必须附的证据 | 不适用时的写法 |
|---|---|---|
| 「隐私合规 / 数据可删除 / 无过度暴露 / 满足 GDPR/个保法」 | ① 字段级 PII 分类表 + 每个读接口响应白名单比对结果（无越权敏感字段）；② **删除权验证**：删除后主库 + 缓存/索引/副本的不可复原证据；③ 数据最小化与存储限制的证据（采集字段清单 vs 必要项、留存策略）；④ 日志脱敏核查结果 | 不处理任何个人数据的纯技术工具、无 PII 的离线脚本 → 只写「未做隐私合规验证」，**不得**写「隐私合规 / 数据可删除 / 满足 GDPR」 |

推论：**「接口返回 200」不能推出「没多给数据」**；**「主库删了」不能推出「全链路删干净了」**。缺副本/日志核查时结论降级为「待确认」。

## 8. L0 零依赖降级路径（工具全缺也能走完）

```bash
# 静态查响应里是否夹带敏感字段名（仅作线索，非判定）
curl -s "$URL/api/me" | grep -oE '"(password|token|secret|ssn|idCard|salary|role|isAdmin)"'
# 查日志中是否落了明文敏感信息
git grep -nEi '(password|token|secret|Bearer)' -- '*.log' 'logs/' 2>/dev/null
# 查代码中 PII 字段定义处是否有最小化/留存标注
git grep -nEi '(ssn|idCard|phone|email|address)' -- '*.ts' '*.py' '*.go' 2>/dev/null
```

降级时报告固定写一行：「本轮仅做**静态 PII 线索扫描**，未做运行时删除权端到端验证（需真实账号与多副本环境）」，并标 `BLOCKED` 而非 Pass。
