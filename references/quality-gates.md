# 缺陷、门禁与测试有效性（阶段 3/4 通用）

> 蒸馏自 `fullstack-dev/references/release-checklist.md`（证据门禁）、`naodeng/awesome-qa-skills` 的 bug-reporting / flaky-test-analysis / ai-generated-test-review / quality-gate-design、变异测试与蜕变测试的工程实践。
> 主张：**测试的产物不是"跑了多少条"，而是"有没有可信的证据"**。

## 1. 缺陷报告八字段（缺一不收）

模板见 `assets/bug-report-template.md`。八字段：

| # | 字段 | 要求 |
|---|---|---|
| 1 | 标题 | `[模块] 行为 + 触发条件`，不含"好像/可能" |
| 2 | 严重度 / 优先级 | 见 §2，两者分开填 |
| 3 | 环境指纹 | OS、运行时版本、commit/版本、浏览器、启动参数 |
| 4 | 最小可复现实例 (MRE) | **可原样粘贴执行**的命令/操作序列，去掉一切无关步骤 |
| 5 | 预期 vs 实际 | 两侧都写，实际侧贴输出原文 |
| 6 | 证据 | 输出片段 / 截图路径 / 日志行；不写"我记得报了个错" |
| 7 | 影响面 | 哪些用户/数据/流程受影响，是否可绕过 |
| 8 | 修复方向（可选） | 给方向不定结论，避免越俎代庖 |

**纪律**：推测标"待确认"；证据必须当场留；复现命令中的 token/密码用 `$TOKEN` 脱敏；临时探针放 `.test-memory/tmp/` 用完即删。

## 2. 严重度 × 优先级矩阵

| 严重度 | 定义 | 默认优先级 |
|---|---|---|
| **S1 严重** | 数据损坏/丢失、越权、认证绕过、注入生效、崩溃、资金错误 | P0，上线阻断 |
| **S2 一般** | 功能错误但有绕过、500 泄漏堆栈、缺限流、大数据量超时 | P1，上线前修 |
| **S3 轻微** | 提示看不懂、空态缺失、文案、轻微视觉 | P2，可排期 |

允许偏离但要写理由：低频边缘 S2 可降优先级；高频主路径 S3 可升。**严重度描述后果，优先级描述排期**，别混用。

## 2A. 判 bug 的十五条标准（阶段 3 用）

命中任一条即为 bug；先写清"哪一条 + 证据"，再定严重度。

| # | 判据 | 一句话说明 | 见 |
|---|---|---|---|
| 1 | **崩溃裸奔** | 进程退出、白屏、未捕获异常直接抛给用户 | `frontend-testing.md` §5 |
| 2 | **报错看不懂或静默失败** | 用户不知发生了什么；或操作失败却提示成功 | `error-contract-testing.md` §10 |
| 3 | **数据损坏 / 状态错乱** | 写坏、丢失、重复、不可逆，或状态机进入非法态 | `data-integrity-testing.md` |
| 4 | **安全漏洞** | 越权、注入、认证绕过、敏感信息泄漏、可伪造令牌 | `security-testing.md` |
| 5 | **不符宣称** | 文档/README/宣传承诺的行为与实测不符 | `dissect.md` §2 |
| 6 | **前端五态缺失 / 焦点不可见** | 空态·加载·错误·无权限·超时缺一，或键盘焦点看不见 | `frontend-testing.md` §4 |
| 7 | **跨租户泄漏 / 制品对不上 / locale 与 RTL 漂移** | 隔离失效、SBOM 与实物不符、翻译溢出或镜像布局错位 | `multi-tenancy-testing.md` · `supply-chain-testing.md` · `i18n-localization-testing.md` |
| 8 | **焦点被遮挡 / 目标过小 / 仿真被写成真机 / 移动集成面未测 / 桌面进程边界未测** | 2.4.11 遮挡、2.5.8 尺寸不足、仅仿真即宣称真机通过；权限/中断/深链/推送/升级未测却称「移动端可用」；nodeIntegration/sandbox/fuses 未核对、IPC 无入参校验却称「桌面端安全」 | `accessibility-testing.md` · `cross-platform-testing.md` · `mobile-app-testing.md` · `desktop-app-testing.md` |
| 9 | **令牌可伪造 / 会话不可终止** | `alg=none` 被接受、登出后旧令牌仍可用 | `auth-session-testing.md` |
| 10 | **DST 双跑漏跑 / 备份不可恢复** | 转换日任务重复或跳过；备份任务成功但恢复失败 | `time-correctness-testing.md` · `backup-recovery-testing.md` |
| 11 | **金额精度与分摊 / webhook 重放与重复副作用** | 展示价≠实扣价、分摊丢分；同事件触发多次扣款/发货 | `money-correctness-testing.md` · `webhook-delivery-testing.md` |
| 12 | **分页重漏 / 5xx 泄漏** | 翻页出现重复或遗漏；5xx 响应体含堆栈、路径、SQL | `query-pagination-testing.md` · `error-contract-testing.md` |
| 13 | **搜索结果不可复现 / 指标对不上** | 同 query 两次排序不同；看板与源表差异超阈值 | `search-quality-testing.md` · `metrics-correctness-testing.md` |
| 14 | **超卖 / 丢失更新** | 并发下库存为负、余额被覆盖、同键副作用 > 1 | `idempotency-concurrency-testing.md` |
| 15 | **评测无统计结论** | 无基线、无 n、无 CI、judge 未校准即宣称"效果更好" | `llm-eval-testing.md` |

## 3. Go / No-Go 决策（默认门槛）

| 条件 | 判定 |
|---|---|
| 存在未闭环 S1 | **No-Go**，无条件 |
| P0 功能点覆盖 < 100% | No-Go 或明确书面例外 |
| P1 覆盖 < 80% | 写明剩余风险 |
| 失败结论无证据 | 该结论作废，不算覆盖 |
| 发布验收场景 | 走 `fullstack-integration.md` §6 的 12 分门禁 |
| 错误预算已耗尽 | 即使功能全绿也 **No-Go**（`observability-testing.md` §4） |
| **任一声称缺 R-N 证据** | 该结论**作废，降为「待确认」**，只写「未做 X 验证」或「不适用：原因」；逐条要求见 §3A |
| 拿"近似证据"冒充充分证据 | 结论作废（清单见 §3B） |

报告末尾必须给一句明确结论：`质量状态：PASS / FAIL` + `发布建议：Go / No-Go` + 一句话理由。禁止"基本可以""问题不大"。

## 3A. R-1~R-26 证据要求（全文）

**二十六条可证伪规则**（v1.1 引入 R-1/R-2，v1.2 引入 R-3/R-4，v1.3 引入 R-5/R-6，v1.4 引入 R-7/R-8，v1.5 引入 R-9，v1.6 引入 R-10，v1.7 引入 R-11，v1.8 引入 R-12，v1.9 引入 R-13/R-14，v1.10 引入 R-15/R-16，v1.11 引入 R-17/R-18，v1.12 引入 R-19/R-20，v1.13 引入 R-21/R-22，v1.14 引入 R-23/R-24，v1.17 引入 R-25，v1.18 引入 R-26）。`SKILL.md` 只留判据骨架，**逐条证据要求以本节为准**。

| 规则 | 结论必须附的证据 | 不适用时的写法 |
|---|---|---|
| **R-1 链路** | 声称"链路完整 / 副作用已发生"，须有同一 `trace_id` 或 `request_id` 贯穿 **≥2 个组件**的原始日志行或 span，并写明采样窗口与样本数 | 单进程、无日志/埋点的 CLI/库/静态页 → 只写「可观测性缺口 / 未做链路验证」，**不得**判 Pass |
| **R-2 韧性** | 声称"依赖故障下仍可用 / 具备韧性"，须附可复现的故障注入记录：注入点、时长、爆炸半径、稳态前后值、对照组、恢复时长、撤销证据 | 无外部依赖、或用户禁止变更环境 → 只写「未做故障注入验证」，**不得**写「具备韧性」 |
| **R-3 制品完整性** | 声称"交付物可信 / 依赖清单完整 / 供应链安全"，须附每个制品的 `sha256` + SBOM 原件（含 direct/transitive、生成器版本、覆盖缺口）+ 签名或 provenance 验证的**命令原文、退出码、输出行** + 扫描输出（工具版本、数据源、时间戳、per-CVE 抑制理由） | 纯源码/脚本/静态页、无构建产物、离线 → 只写「未做制品完整性验证」，**不得**写「供应链安全 / 无已知漏洞」 |
| **R-4 租户隔离** | 声称"租户隔离有效 / 无跨租户泄漏"，须附双租户相同 ID 夹具 + 一票否决四条逐条否定路径结果 + 连接复用、noisy-neighbor、双租户备份恢复三项原始输出 + intentional sharing 的 "no broader access" 证据 | 单租户、无共享资源、禁止构造第二租户 → 只写「未做租户隔离验证 / 不适用」，**不得**写「隔离良好」 |
| **R-5 契约演进** | 声称"API 向后兼容 / 升级可安全部署 / 老客户端不受影响"，须附 ① `oasdiff breaking --fail-on=ERR` 的命令原文 + 退出码 + 输出行（baseline 与修订版明确）；② 若有消费者，Pact verify 绿 + `can-i-deploy` 目标环境退出码 0；③ 容忍读取验证（老客户端对新增字段不报错） | 无对外契约的单体工具、无版本概念 demo → 只写「未做契约演进验证」，**不得**写「向后兼容 / 老客户端不受影响」 |
| **R-6 隐私与数据生命周期** | 声称"隐私合规 / 数据可删除 / 无过度暴露 / 满足 GDPR·个保法"，须附 ① 字段级 PII 分类表 + 每个读接口响应白名单比对（无越权敏感字段）；② 删除权验证（删除后主库 + 缓存/索引/副本不可复原证据）；③ 数据最小化与存储限制证据；④ 日志脱敏核查 | 不处理任何个人数据的纯技术工具、无 PII 离线脚本 → 只写「未做隐私合规验证」，**不得**写「隐私合规 / 满足 GDPR」 |
| **R-7 无障碍可达性** | 声称"符合 WCAG 2.2 AA / 支持读屏 / 可键盘操作 / 无障碍已验收"，须附 ① 目标版本与级别；② `axe-core` 或等价扫描的 violations **+ incomplete 原文**且 incomplete 逐条人工结论；③ 至少一条 P0 流程的完整键盘路径记录（逐步焦点、可见性、2.4.11 遮挡判定）；④ 至少一组读屏 + 浏览器 + OS 组合的逐项 passed/failed/not checked/not present 标注；⑤ 2.5.8 目标尺寸与 3.3.8 认证认知负担实测结论 | 纯 CLI / 无 UI 的库 / 批处理脚本、无图形交互界面 → 只写「不适用：无图形交互界面，未做无障碍实测」，**不得**写「无障碍合规 / 符合 WCAG」；无读屏环境只写「未做读屏实测」，结论降为「待确认」 |
| **R-8 跨端与设备形态真实性** | 声称"移动端可用 / 兼容主流浏览器 / 已适配折叠屏 / 跨端已验证 / 真机验过"，须附 ① 设备矩阵来源（install-base analytics 数据源 + 时间窗）与覆盖占比；② `real`/`emulator`/`simulator`/`browser-emulation` 逐项载体标注；③ 不同浏览器内核实测；④ 长尾条目（低配/最老受支持 OS/厂商皮肤/折叠屏平板）逐条结论或显式未覆盖；⑤ 生命周期、中断、权限、旋转、深链、网络档位的实际输出；⑥ 声称真机须有 ≥1 组 real device 记录 | 纯后端 API / CLI / 无 UI 的库 → 只写「不适用：无终端形态差异，未做跨端验证」，**不得**写「跨端已验证」；只有仿真时写「仅完成仿真验证，未做真机验证」并降为「待确认」，**不得**写「真机验过 / 全平台兼容」 |
| **R-9 证据链可追溯与可复核性** | 声称"测试结论可复核 / 证据链完整 / 已通过审计 / 合规声明有证据支撑"，须附 ① 每条结论 → 证据文件 → 原始输出的三级引用链且锚点可解析（行号存在或片段命中）；② 证据 `sha256` + 被测对象 commit / 环境指纹 / 时间窗绑定（无 `stale_evidence`）；③ `scripts/evidence-audit.py` 自动对账结果含覆盖缺口、悬空引用、过期证据与四类结论区分；④ 合规声明 → 控制项 → 证据的映射表与未映射项声明；⑤ 审计导出件自身 hash 与生成时间 | 一次性探索测试、无留档要求的临时验证 → 只写「未做证据链对账 / 不适用：无留档要求」，**不得**写「可审计 / 证据链完整 / 通过审计」；只有部分证据时写「证据链存在 N 处缺口，结论降级为待确认」，**不得**写「证据齐全」，**不得**把对账 GREEN 冒充「合规通过」 |
| **R-10 特性开关 / 配置 / 灰度正确性** | 声称"开关关掉系统还安全 / kill-switch 能止血 / 灰度可控 / 配置正确 / 目标群体隔离"或"开关两态都测过"，须附 ① 开关 off 态与**缺失态**（配置不可达）都回退到声明的安全路径、且无残留新副作用的实测；② 目标群体命中变体的同时，非目标群体的否定用例（不得泄露）；③ env / 文件 / 远程配置三处的比对与优先级声明，或明确写「无外部化配置」；④ kill-switch 真关后回到安全态的实测；⑤ 灰度比例实测采样（计划 vs 实际）与「一键停」能力 | 纯静态、无任何开关 / 配置化 / 灰度放量的离线脚本 → 只写「不适用：无开关与配置维度」，**不得**写「开关安全 / 灰度可控」；只有部分证据时写「证据链存在 N 处缺口，R-10 降级为待确认」，**不得**写「开关可控 / 灰度安全」，**不得**把「开态测过」冒充「关态也安全」 |
| **R-11 测试数据可信与合规** | 声称"测试数据已脱敏 / 合成数据无 PII 泄漏 / 数据可复现 / 子集引用完整 / 没用生产数据"，须附 ① 数据来源声明（合成种子值 / 脱敏命令原文 + 退出码 / 明确"未使用生产数据"）；② 脱敏字段清单 + 掩码后**残留核查** + 人工复核结论；③ 同一 `--seed` 两次生成逐字节一致的校验值；④ 子集外键悬空数 = 0 的核查命令与输出；⑤ 测试环境无生产 host、临时含 PII 数据已退役的声明 | 纯静态算法库、无数据依赖的纯离线脚本 → 只写「不适用：无测试数据维度」，**不得**写"测试数据可信 / 数据已脱敏 / 数据可复现"；只有部分证据时写「测试数据存在 N 处缺口，R-11 降级为待确认」，**不得**把"用了生成器"冒充"数据已脱敏"，**不得**把"掩码了已知字段"冒充"无 PII 泄漏" |
| **R-12 身份与会话不可冒充** | 声称"认证安全 / JWT 校验正确 / 令牌不可伪造 / 登出即失效 / 支持 MFA / 会话已终止"，须附 ① 令牌清单与存放位置（Authorization / Cookie / URL / localStorage / 日志）+ `scripts/jwt-audit.py decode` 的结构审计输出（alg / exp / aud / iss / kid / jku 结论）；② `alg=none`、算法混淆、空签名三类伪造请求的**请求原文 + 响应码 + 响应体**（拒绝才算通过）；③ 过期 / 未来时间 / 错 `aud` / 错 `iss` / 类型混用五类负向用例逐条结果；④ 登出、改密、重置后旧 access **与** refresh 均被拒的实测；⑤ 刷新轮换与旧 refresh 重用（reuse detection、family 失效）证据，或明确声明未实现并降级；⑥ 账户枚举三列对照（状态码 / 响应体 / 响应时间）+ 限流触发记录；⑦ 密码存储（算法 / 参数 / 每用户 salt）源码证据 | 无认证的静态页、无会话状态的纯离线库/CLI → 只写「不适用：无身份与会话维度」，**不得**写「认证安全 / 令牌不可伪造」；只有黑盒、无源码时密码存储写「未验证（需源码审计）」，**不得**写「密码已加盐哈希」；只有部分证据时写「身份与会话存在 N 处缺口，R-12 降级为待确认」，**不得**把「登录成功」冒充「认证安全」，**不得**把「令牌能解码」冒充「能伪造」，**不得**把「Cookie 有 HttpOnly」冒充「会话安全」 |

## 4. Flaky 测试治理（重试 ≠ 修复）

flaky = 代码没变、同一测试时过时不过。治理顺序：

1. **确认**：同一用例连续跑 10 次记录通过率；换机器/换顺序再跑，区分"环境相关"与"用例相关"
2. **定位三查**（按命中率排序）：
   - 共享状态 / 未清理（DB、文件、全局单例、时间、随机数）
   - 异步等待（固定 `sleep`、隐式等待、未 await）
   - 外部依赖（网络、时钟、第三方服务）
3. **修复**：自 setup/teardown、显式等待条件、注入时钟/随机种子、HTTP 层 mock
4. **隔离**：修不好就 `quarantine` 并登记，带负责人与解除日期；**不许直接删、不许无限重试**
5. **记录**：写进项目 `lessons.md` 标签 `[工具]`，通用规律进 `memory/global-lessons.md`

> 反模式：给 CI 加 `retries: 3` 就宣称"稳定了"。这只会把不确定性藏起来，并让真实回归更晚被发现。

## 5. 覆盖率与变异测试（识破"假测试"）

| 指标 | 回答的问题 | 陷阱 |
|---|---|---|
| 行/分支覆盖率 | 代码被执行过吗？ | 执行了但没断言，照样 95% |
| 功能点覆盖 | 测试矩阵跑了多少？ | 只数条数不看质量 |
| **变异得分** | 故意把代码改坏，测试能抓到吗？ | 低分 = 一堆伪测试 |

```bash
# 按栈选一个（无工具则跳过并注明）
npx stryker run                    # JS/TS
pip install mutmut && mutmut run   # Python
mvn org.pitest:pitest-maven:mutationCoverage  # Java
cargo mutants                     # Rust
```

**AI 生成测试尤其要查这一项**：常见伪测试特征——只断言 `is not None` / `isinstance` / `assertTrue`、断言调用过 mock 却不断言业务结果、把实现复制一遍当预期、用 `expect(...).toBeTruthy()` 收尾。审查清单见 `ai-native-testing.md` §3。

判据：核心模块变异得分明显偏低时，报告写"**覆盖率虚高，测试杀伤力不足**"，并补强断言，而不是把覆盖率数字当结论。

## 6. CI 质量门禁（可落地的最小集）

| 门禁 | 实现 | 失败动作 |
|---|---|---|
| 测试全绿 | `npm test` / `pytest` / `go test ./...` | 阻断合并 |
| 覆盖率阈值 | `--coverage --check-coverage` ≥ 约定值（建议 80%，但见 §5  caveat） | 阻断或告警 |
| 契约 / schema | Pact verify / schemathesis / OpenAPI diff | 阻断 |
| 依赖漏洞 | `npm audit` / `pip-audit` / `govulncheck` | 高危阻断 |
| 静态检查 | lint / typecheck / secret scan | 阻断 |
| 性能冒烟 | k6 thresholds / 分位数断言 | 关键路径阻断 |
| 套件时长 | 全套 < 15 分钟（超出则并行/选测） | 告警 |

按变更范围**选测**（change-to-regression）：改了哪个模块就跑它的用例 + P0 全量回归；不要每次都全量硬跑，也不要只跑一行改动的那一个用例。

## 7. 指标口径（别用数字美化结论）

- 每个指标写清**分子 / 分母 / 数据源 / 时间窗 / 解释边界**
- 区分「静态记录」「评测准备度」「运行时质量」「发布批准」——目录/文件数量不等于质量
- 缺失证据标 `BLOCKED` / `待确认`，**不填 0 分假装测过**
- 报告里的"通过 X / 失败 Y / 阻塞 Z"，X+Y+Z 必须等于测试点总数 N
