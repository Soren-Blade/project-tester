# 缺陷、门禁与测试有效性（阶段 3/4 通用）

> 蒸馏自 `fullstack-dev/references/release-checklist.md`（证据门禁）、`naodeng/awesome-qa-skills` 的 bug-reporting / flaky-test-analysis / ai-generated-test-review / quality-gate-design、变异测试与蜕变测试的工程实践。
> 主张：**测试的产物不是"跑了多少条"，而是"有没有可信的证据"**。

## 1. 缺陷报告八字段（缺一不收）

模板见 `assets/bug-report-template.md`。八字段：

| # | 字段 | 要求 |
|---|---|---|
| 1 | 标题 | `[模块] 行为 + 触发条件`，不含"好像/可能" |
| 2 | 严重度 / 优先级 | 见 §2，两者分开填 |
| 3 | 环境指纹 | OS、运行时版本、commit/版本、浏览器、启动参数 |
| 4 | 最小可复现实例 (MRE) | **可原样粘贴执行**的命令/操作序列，去掉一切无关步骤 |
| 5 | 预期 vs 实际 | 两侧都写，实际侧贴输出原文 |
| 6 | 证据 | 输出片段 / 截图路径 / 日志行；不写"我记得报了个错" |
| 7 | 影响面 | 哪些用户/数据/流程受影响，是否可绕过 |
| 8 | 修复方向（可选） | 给方向不定结论，避免越俎代庖 |

**纪律**：推测标"待确认"；证据必须当场留；复现命令中的 token/密码用 `$TOKEN` 脱敏；临时探针放 `.test-memory/tmp/` 用完即删。

## 2. 严重度 × 优先级矩阵

| 严重度 | 定义 | 默认优先级 |
|---|---|---|
| **S1 严重** | 数据损坏/丢失、越权、认证绕过、注入生效、崩溃、资金错误 | P0，上线阻断 |
| **S2 一般** | 功能错误但有绕过、500 泄漏堆栈、缺限流、大数据量超时 | P1，上线前修 |
| **S3 轻微** | 提示看不懂、空态缺失、文案、轻微视觉 | P2，可排期 |

允许偏离但要写理由：低频边缘 S2 可降优先级；高频主路径 S3 可升。**严重度描述后果，优先级描述排期**，别混用。

## 3. Go / No-Go 决策（默认门槛）

| 条件 | 判定 |
|---|---|
| 存在未闭环 S1 | **No-Go**，无条件 |
| P0 功能点覆盖 < 100% | No-Go 或明确书面例外 |
| P1 覆盖 < 80% | 写明剩余风险 |
| 失败结论无证据 | 该结论作废，不算覆盖 |
| 发布验收场景 | 走 `fullstack-integration.md` §6 的 12 分门禁 |
| 声称链路完整 / 副作用已发生但无 R-1 证据 | 结论作废，降为「待确认」（`observability-testing.md` §8） |
| 声称具备韧性但无 R-2 故障注入记录 | 结论作废，只写「未做故障注入验证」（`chaos-resilience.md` §8） |
| 声称「交付物可信 / 依赖清单完整 / 供应链安全」但无 R-3 证据 | 结论作废，降为「待确认」，只写「未做制品完整性验证」（`supply-chain-testing.md` §7） |
| 声称「租户隔离有效 / 无跨租户泄漏」但无 R-4 证据 | 结论作废，降为「待确认」，只写「未做租户隔离验证」（`multi-tenancy-testing.md` §9） |
| 声称「API 向后兼容 / 升级可安全部署 / 老客户端不受影响」但无 R-5 证据 | 结论作废，降为「待确认」，只写「未做契约演进验证」（`contract-evolution-testing.md` §6） |
| 声称「隐私合规 / 数据可删除 / 无过度暴露 / 满足 GDPR·个保法」但无 R-6 证据 | 结论作废，降为「待确认」，只写「未做隐私合规验证」（`privacy-compliance-testing.md` §7） |
| 声称「符合 WCAG 2.2 AA / 支持读屏 / 可键盘操作 / 无障碍已验收」但无 R-7 证据 | 结论作废，降为「待确认」，只写「未做无障碍实测」（`accessibility-testing.md` §5）；**axe 0 violations 或 `incomplete` 未复核不算证据** |
| 声称「移动端可用 / 兼容主流浏览器 / 跨端已验证 / 真机验过」但无 R-8 证据 | 结论作废，降为「待确认」，只写「未做跨端验证 / 仅完成仿真验证」（`cross-platform-testing.md` §7）；**仿真绿不算真机证据** |
| 声称「测试结论可复核 / 证据链完整 / 已通过审计 / 合规声明有证据支撑」但无 R-9 证据 | 结论作废，降为「待确认」，只写「未做证据链对账 / 证据链存在 N 处缺口」（`evidence-chain-audit.md` §7）；**报告写全了、证据文件都在、对账 GREEN 都不算合规通过** |
| 声称「开关关掉系统还安全 / kill-switch 能止血 / 灰度可控 / 配置正确 / 目标群体隔离」但无 R-10 证据 | 结论作废，降为「待确认」，只写「未做开关/配置/灰度验证」（`feature-flag-testing.md` §4）；**「开态测过」不算「关态也安全」、配置三处一致没比对不算「配置正确」、说 5% 没实测采样不算「灰度可控」** |
| 声称「测试数据已脱敏 / 合成数据无 PII 泄漏 / 数据可复现 / 子集引用完整 / 没用生产数据」但无 R-11 证据 | 结论作废，降为「待确认」，只写「未做测试数据可信验证」（`test-data-management.md` §6）；**「用了生成器」不算「数据已脱敏」、掩码了已知字段不算「无 PII 泄漏」、无 `--seed` 却说「数据可复现」不算证据、连生产库抽数本身即 S1 反模式** |
| 声称「认证安全 / JWT 校验正确 / 令牌不可伪造 / 登出即失效 / 支持 MFA / 会话已终止」但无 R-12 证据 | 结论作废，降为「待确认」，只写「未做身份与会话验证 / 身份与会话存在 N 处缺口」（`auth-session-testing.md` §7）；**「登录成功」不算「认证安全」、「令牌能解码」不算「能伪造」、Cookie 有 HttpOnly 不算「会话安全」、alg=none 被接受即 No-Go** |
| 声称「时间显示正确 / 跨时区一致 / DST 无影响 / 令牌按时过期 / 定时任务可靠」但无 R-13 证据 | 结论作废，降为「待确认」，只写「未做时间与时区验证 / 时间面存在 N 处缺口」（`time-correctness-testing.md` §9）；**「能解析时间」不算「时区正确」、静态扫描未命中不算「时间逻辑正确」、服务器跑 UTC 不算「DST 无影响」；DST 转换日任务双跑产生重复副作用且无幂等键即 S1** |
| 声称「有备份 / 可恢复 / 满足 RPO·RTO / 数据不丢」但无 R-14 证据 | 结论作废，降为「待确认」，只写「未做过恢复演练 / 备份面存在 N 处缺口」（`backup-recovery-testing.md` §8）；**「备份任务成功」不算「可恢复」、结构校验通过不算「内容完整」、没在隔离环境实恢复过一次不算「有备份」；恢复点早于备份、恢复后主键冲突即 S1** |
| 声称「金额算得对 / 账记平衡 / 对账通过 / 多币种正确 / 退款不超额」但无 R-15 证据 | 结论作废，降为「待确认」，只写「未做金额与账务验证 / 金额面存在 N 处缺口」（`money-correctness-testing.md` §5）；**「显示价对」不算「扣款额对」、「库内借贷平衡」不算「对账通过」、「用了 decimal 类型」不算「舍入正确」；展示价≠实扣价、分摊丢分、重复扣款、账本不平即 S1，且判 bug 必须给出差额的最小单位数** |
| 声称「消息必达 / webhook 可靠 / 不丢不重 / 幂等已做 / 回调安全」但无 R-16 证据 | 结论作废，降为「待确认」，只写「未做异步交付可靠性验证 / 交付面存在 N 处缺口」（`webhook-delivery-testing.md` §7）；**「验签通过」不算「不可伪造」、「返回 2xx」不算「业务已处理」、「重试配置存在」不算「重试生效」；重复事件导致重复扣款/发货、验签缺失或可绕过、回 2xx 但未落库即 S1，重放窗与去重窗口必须实测** |
| 错误预算已耗尽 | 即使功能全绿也 **No-Go**（`observability-testing.md` §4） |

报告末尾必须给一句明确结论：`质量状态：PASS / FAIL` + `发布建议：Go / No-Go` + 一句话理由。禁止"基本可以""问题不大"。

## 4. Flaky 测试治理（重试 ≠ 修复）

flaky = 代码没变、同一测试时过时不过。治理顺序：

1. **确认**：同一用例连续跑 10 次记录通过率；换机器/换顺序再跑，区分"环境相关"与"用例相关"
2. **定位三查**（按命中率排序）：
   - 共享状态 / 未清理（DB、文件、全局单例、时间、随机数）
   - 异步等待（固定 `sleep`、隐式等待、未 await）
   - 外部依赖（网络、时钟、第三方服务）
3. **修复**：自 setup/teardown、显式等待条件、注入时钟/随机种子、HTTP 层 mock
4. **隔离**：修不好就 `quarantine` 并登记，带负责人与解除日期；**不许直接删、不许无限重试**
5. **记录**：写进项目 `lessons.md` 标签 `[工具]`，通用规律进 `memory/global-lessons.md`

> 反模式：给 CI 加 `retries: 3` 就宣称"稳定了"。这只会把不确定性藏起来，并让真实回归更晚被发现。

## 5. 覆盖率与变异测试（识破"假测试"）

| 指标 | 回答的问题 | 陷阱 |
|---|---|---|
| 行/分支覆盖率 | 代码被执行过吗？ | 执行了但没断言，照样 95% |
| 功能点覆盖 | 测试矩阵跑了多少？ | 只数条数不看质量 |
| **变异得分** | 故意把代码改坏，测试能抓到吗？ | 低分 = 一堆伪测试 |

```bash
# 按栈选一个（无工具则跳过并注明）
npx stryker run                    # JS/TS
pip install mutmut && mutmut run   # Python
mvn org.pitest:pitest-maven:mutationCoverage  # Java
cargo mutants                     # Rust
```

**AI 生成测试尤其要查这一项**：常见伪测试特征——只断言 `is not None` / `isinstance` / `assertTrue`、断言调用过 mock 却不断言业务结果、把实现复制一遍当预期、用 `expect(...).toBeTruthy()` 收尾。审查清单见 `ai-native-testing.md` §3。

判据：核心模块变异得分明显偏低时，报告写"**覆盖率虚高，测试杀伤力不足**"，并补强断言，而不是把覆盖率数字当结论。

## 6. CI 质量门禁（可落地的最小集）

| 门禁 | 实现 | 失败动作 |
|---|---|---|
| 测试全绿 | `npm test` / `pytest` / `go test ./...` | 阻断合并 |
| 覆盖率阈值 | `--coverage --check-coverage` ≥ 约定值（建议 80%，但见 §5  caveat） | 阻断或告警 |
| 契约 / schema | Pact verify / schemathesis / OpenAPI diff | 阻断 |
| 依赖漏洞 | `npm audit` / `pip-audit` / `govulncheck` | 高危阻断 |
| 静态检查 | lint / typecheck / secret scan | 阻断 |
| 性能冒烟 | k6 thresholds / 分位数断言 | 关键路径阻断 |
| 套件时长 | 全套 < 15 分钟（超出则并行/选测） | 告警 |

按变更范围**选测**（change-to-regression）：改了哪个模块就跑它的用例 + P0 全量回归；不要每次都全量硬跑，也不要只跑一行改动的那一个用例。

## 7. 指标口径（别用数字美化结论）

- 每个指标写清**分子 / 分母 / 数据源 / 时间窗 / 解释边界**
- 区分「静态记录」「评测准备度」「运行时质量」「发布批准」——目录/文件数量不等于质量
- 缺失证据标 `BLOCKED` / `待确认`，**不填 0 分假装测过**
- 报告里的"通过 X / 失败 Y / 阻塞 Z"，X+Y+Z 必须等于测试点总数 N
