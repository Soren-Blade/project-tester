# Webhook / 异步消息交付可靠性测试矩阵（R-16）

> 用法：复制本文件到 `<目标项目>/.test-memory/webhook-matrix.md`，逐行填「实测值 + 证据位置 + 结论」。
> 规则：**没有证据的位置不得写 PASS**；没测的行写 `未测`，不适用的行写 `不适用：<理由>`；没拿到渠道侧记录时**不得**写「消息必达」。
> 配套：`references/webhook-delivery-testing.md`、`scripts/webhook-audit.py`。

## 1. 六个面 × 用例

| ID | 面 | 用例（最小动作） | 期望（判据） | 实测值 | 证据 | 结论 |
|---|---|---|---|---|---|---|
| D-01 | 签名 | 正常签名请求 | 200；验签通过后再处理业务 | | | |
| D-02 | 签名 | 改 1 字节 body | 401/400 拒绝，业务零副作用 | | | |
| D-03 | 签名 | 用旧消息的签名+新 body | 拒绝（签名覆盖 id+timestamp+body） | | | |
| D-04 | 签名 | 重放 10 分钟前的合法请求 | 超出容忍窗拒绝；窗内重放由幂等兜住 | | | |
| D-05 | 签名 | 缺签名头 / 空签名 / 错误 scheme | 拒绝，不落业务；日志可定位 | | | |
| D-06 | 幂等 | 同一 event_id 连发 5 次 | 业务只生效 1 次；5 次都返回 2xx（或契约码） | | | |
| D-07 | 幂等 | 同 event_id 并发 10 请求 | 只生效 1 次；无死锁、无重复扣款 | | | |
| D-08 | 幂等 | 去重键过期后重放 | 按契约行为；若会重复生效必须写清窗口风险 | | | |
| D-09 | 重试 | 下游持续 500 | 按退避重试，间隔递增；总次数符合声明 | | | |
| D-10 | 重试 | 下游恢复后 | 积压消息最终送达，且不重复生效 | | | |
| D-11 | 重试 | 重试期间进程重启 | 待重试消息不丢（持久化），重启后继续 | | | |
| D-12 | 重试 | 4xx（不可重试） | 不盲目重试；进 DLQ 或标记终态 | | | |
| D-13 | 顺序 | 同一订单 created→paid→shipped 乱序到达 | 业务按序号/状态机拒绝倒退，或补偿；不出现「先发货后付款」 | | | |
| D-14 | 顺序 | 序号相同/缺失 | 有确定裁决规则，不随机 | | | |
| D-15 | 丢失 | 消费者处理后、回 2xx 前崩溃 | 渠道重试；消费者幂等，最终只生效 1 次 | | | |

| D-19 | 观测 | 失败率与积压 | 有指标/告警阈值；积压可见 | | | |
| D-20 | 对账 | 渠道侧事件数 与 本地生效数 | 差异可解释（重复/丢失/过滤），不靠抽样 | | | |

## 3. 盲区与降级声明

| 盲区 | 原因 | 影响 | 降级结论 |
|---|---|---|---|
| 无渠道沙箱/无真实回调 | 无商户号或回调地址不可达 | 签名与重试策略只能按文档推断 | R-16 降级为「部分覆盖」，不得写「交付可靠」 |
| 无法注入网络故障 | 无 tc/iptables 权限 | 重试与乱序未实测 | 不得写「不丢不重」 |
| 无 DLQ 实现 | 系统未提供 | 最终失败只能人工捞日志 | 只能写「有日志」，不得写「可补偿」 |
| 单实例部署 | 无多副本 | 并发去重未覆盖 | 「不适用：单实例；多副本未测」 |
| 顺序无契约 | 业务未定义 | 无法判定乱序是否缺陷 | `BLOCKED: 顺序语义未定义` |
