## 2. 合规声明 ↔ 控制项 ↔ 证据

| 控制项（声明来源 + 编号） | 关联结论 ID | 评估活动 / 时间窗 / scope | 证据锚点 | finding | 缺口声明 |

| <如 SSDF PS.3.2 provenance> | R-3 | <哪次测试> | `<path>:L<n>` | PASS/FAIL/BLOCKED | <无 / 未覆盖 / 数据不可得> |
| <如 GDPR Art.17 删除权> | R-6 | <哪次测试> | `<path>:L<n>` | <结论> | <缺口> |

- 未映射到任何结论的控制项、未映射到任何控制项的结论，都要在「缺口声明」里显式列出。
- **不得**抄一份框架清单就写「合规通过」；NIST SSDF 明确其意图不是 checklist。

## 3. 对账缺口清单

| 严重度 | 检出码 | 关联结论 | 明细 | 处置 |
|---|---|---|---|---|
| BLOCK / WARN | `dangling_reference` 悬空引用 | R-<n> | 证据文件不存在 | 作废 → 待确认 |
| BLOCK / WARN | `unresolvable_anchor` | R-<n> | 锚点超出行数 / 片段未命中 | 重定位或重采 |
| BLOCK / WARN | `stale_evidence` | R-<n> | 采集 commit ≠ 当前 commit | 重采或标「历史证据」 |
| BLOCK / WARN | `pass_without_proof` | R-<n> | PASS 未登记证据 | 作废 → 待确认 |
| BLOCK / WARN | `unmapped_control` | <控制项> | 指向未登记结论 | 补映射或写缺口 |
| WARN | `unclassified_conclusion` | R-<n> | 四类结论未标注 | 补标注 |

> 无缺口时写「本轮证据链未发现缺口」；**不得**把空表当成「全部通过」。

| 项 | 值 |
